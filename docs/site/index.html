Built for the work integration teams actually do

⚡

Large-message ready

SIMD-accelerated streaming parser with on-demand field truncation. Open multi-megabyte ORU^R01 messages with base64 attachments in under two seconds. The editor never shows you 10 MB of raw text.

🔗

Client & listener, bidirectional

Send via MLLP / HTTP / HTTPS, listen on any port with auto-ACK and a live inbox. Connection profiles are saved per-protocol. Everything works offline against your own test servers.

🔍

Validation & FHIRPath

Structural, field-level and data-type validation out of the box, plus FHIR conformance against the StructureDefinitions of the built-in R4 core and any FHIR package you install on top — cardinality, element types, choice elements, unknown elements, Bundle references. A full FHIRPath 2.0 evaluator, checked against the official HL7 test suite. Your own rules drop in as declarative JSON plugin packs — no recompile, no code execution.

🛡️

PHI anonymization

21 built-in PHI fields across PID/NK1/IN1/GT1 with sensitivity-aware masking. Extend the catalogue with regional PHI via plugin packs. Structure is preserved so anonymized messages remain valid.

📄

Field Inspector

Right-click any field in the editor or the tree to see the HL7 schema-derived name, type, cardinality, length limits and current value. Coded values are explained inline from the 394 HL7 value tables that ship with the app (M — Male), in the tree, on hover and in auto-completion. Schema-aware tree optionally shows every possible field, not just the populated ones.

🌍

i18n + cross-platform

UI in English, Italian, French, Spanish and German. Native installers for Windows (NSIS + MSI), macOS (DMG) and Linux (.deb, .rpm, AppImage) — with .hl7 file association and language selector.

📐

XSD schema export

Generate a standards-compliant XSD for any HL7 v2 message type in one click. Drop it into Astraia, BizTalk, XMLSpy or any XML-based pipeline that expects a hand-authored schema. Four common messages in v2.5 are free; the full catalogue and other versions come with Pro.

Plugin packs

Your rules — dropped in as JSON.

Every hospital has custom ADT quirks, Z-segments, regional PHI fields. BridgeLab reads declarative JSON packs from a user folder and merges them into the validator and the anonymizer. No code execution, no sandbox surprises.

  • Six check types: not_empty, regex, one_of, max_length, min_length, contains
  • Component-level narrowing via the component field
  • FHIR rule packs too: a FHIRPath invariant, or a selector plus a check
  • Extra PHI fields with sensitivity-aware masking
  • Live reload without restarting the app
  • Per-pack enable/disable, persisted across sessions

The whole mechanism is in every tier. Community keeps up to 3 packs active at once; Pro and Enterprise have no cap. Packs beyond the cap are never deleted — they wait for a free slot.

Frequently asked

Is the core really free for commercial use?

Yes. The core is MIT-licensed and stays fully usable for production integration work. Pro and Enterprise tiers unlock advanced features — MLLP listener, PHI masking and batch tools, FHIRPath, the full XSD catalogue, priority support — plus the SOAP 1.1/1.2 client with WS-Security and a team test case library (coming soon), but nothing that blocks day-to-day HL7 work.

How much does Pro cost?

Pro is €249 per seat per year (launch offer: €199 for the first year, first 20 licenses). Enterprise is €499/year and adds priority support plus the SOAP 1.1/1.2 client with WS-Security (WSDL import coming soon). One seat covers two activations, e.g. desktop + laptop. Prices exclude VAT; multi-seat discounts from 3 seats.

How does activation and renewal work?

You receive an activation code (BL-PRO-XXXX-XXXX-XXXX) by e-mail. Paste it into the License dialog: the app makes a single HTTPS call, receives a signed license and from then on everything is verified locally — no heartbeat, no phone-home required. When you renew, the same code is extended server-side — no new code to distribute: the app picks the new expiry up on its own within two weeks of expiry, or instantly via Update license in the License dialog. Air-gapped machine? Write to info@techemv.it with your Hardware ID for an offline key.

What happens when my subscription expires?

BridgeLab keeps working: it falls back to the Community tier with a renewal banner. Your files, plugins and test cases stay untouched. Renew and re-paste your code to re-enable Pro features on the spot.

Can I point BridgeLab at a real live feed?

That is the primary use case. Start a listener on port 2575, send HL7 via MLLP from your feed, see received messages in the inbox and open any of them in a new editor tab. Auto-ACK is configurable per listener.

How do you handle 10 MB messages with base64 PDFs?

The Rust backend uses a streaming zero-copy parser with field-level truncation. The editor receives truncated text ({...N bytes} markers) so Monaco is never asked to render megabytes. Expansion is on-demand via right-click or per-field.

Does it work offline?

Fully. Parsing, validation, MLLP and HTTP targeting local hosts, anonymization, export, CLI — none require network access. Activating with an online activation code needs a single HTTPS call; afterwards the license is verified locally via Ed25519 signatures with no license server involved. Fully offline signed keys are available on request for air-gapped sites.

What about PHI and data residency?

BridgeLab processes every message locally. Nothing leaves your machine unless you explicitly send it via the Communication panel. Telemetry is off by default and, when enabled in Settings → Privacy, carries only anonymous usage counters — the exact JSON payload can be previewed in the app before opting in.

How do plugins work?

Drop a JSON file in <config>/BridgeLab/plugins/validation/, /fhir/ or /anonymization/. The app loads it at startup or on demand via Settings → Plugins. No code runs — plugins are declarative rules. Every tier runs every kind of pack; Community keeps up to 3 active at once, Pro has no cap. See PLUGINS.md.

Which HL7 versions are supported?

v2.1 through v2.7.1 for segment / field schemas (ten versions, 2,320 selectable message structures) plus the 394 HL7 value tables behind the coded fields. Custom (Z-) segments parse and edit cleanly, they just fall back to raw values in the Field Inspector unless you ship a plugin pack for them.

Is there a CLI?

Yes — bridgelab-cli validate, info, anonymize, to-json, batch. Outputs JSON or JUnit XML so you can wire it into CI.
