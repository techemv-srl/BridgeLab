# BridgeLab 2.0.0 — fixes and improvements

This page lists the fixes in 2.0.0, grouped by area. New features are described in the release notes. The [CHANGELOG](../../CHANGELOG.md) has every detail.

Two notes come first because they may be worth a moment of your time.

## Two things worth checking

### Anonymization

Earlier versions masked the main patient identifiers (name, identifiers, address and phone numbers in PID, and the core fields of NK1, GT1 and IN1). Some personal fields of those segments were not in the catalogue. Among them:

- dates of birth of the guarantor and the insured;
- the insured's address;
- the social security number in IN2;
- the patient's birth place and death date;
- the visit number;
- some contact details of next of kin.

In 2.0 the catalogue follows the HL7 v2.5 definitions of PID, PV1, MRG, NK1, GT1, IN1 and IN2, plus NTE comments and free-text OBX results (89 fields). The dialog, batch anonymize, the CLI and test-pack masking share it.

**If you prepared anonymized files with an earlier version to share them outside your organisation, we recommend running them through 2.0 again.** Re-run the originals, not the anonymized copies, since the fields that were kept are already in the output.

### Messages with very long fields

Earlier versions showed long values, such as base64 attachments, in a shortened form in the editor. In some cases Save, Save As and the saved session could write that shortened form to disk. In 2.0 the editor always holds the complete message and folds long values only on screen, so saving always writes the full text.

**If you edited and saved messages with very long fields in an earlier version, compare them with their source.** The original files you did not edit are not affected.

## HL7 v2 editing

- The tree draws only the rows on screen, so messages and logs with thousands of segments stay responsive; arrow keys move through it, and edits keep what was expanded and selected.
- Find and Replace All include text in folded fields.
- Clicking a validation issue selects the right segment or field, also when there are blank lines between segments.
- Insert segment (from the tree) places the segment in its standard position, uses the message's separators and can be undone.
- Files with a byte-order mark, blank lines or MLLP framing before MSH, UTF-16 files and FHS/BHS batch files open and parse; files that do not parse open as text with the reason.
- Saving keeps the file's segment terminators (CR stays CR), its owner, and hard links.
- Save writes to a temporary file first, so a full disk no longer leaves a partial file.
- A read-only file is not replaced on any OS.
- Files changed by another program are detected, and Save asks before overwriting a newer version.
- A paste into a search box or form field no longer replaces the open message; closing a tab with unsaved changes asks first.
- The session keeps the last edits when the window closes and restores each tab with its own message.
- App shortcuts work with the cursor in the editor; F1 opens the manual.
- On macOS, Cmd+Q asks about unsaved tabs and saves the session; menus and Settings show ⌘ shortcuts; Finder's *Open With* opens the file.

## HL7 v2 validation

- Numbers, dates, timestamps and times are checked for format and against the calendar (as warnings).
- Field lengths count characters, not bytes, so accented names are no longer reported over the limit.
- OBX-5 is checked as the type OBX-2 declares; each repetition is checked on its own.
- A message whose version BridgeLab has no catalogue for gets a note naming the version used.

## Character sets

- Latin-1, Windows-1252 and the other ISO 8859 charsets open, validate, anonymize and send in their own charset.
- Big5, GB 18030 and KS X 1001 are supported.
- ISO-8859-1 is handled as real Latin-1.
- Charsets BridgeLab cannot decode are reported instead of being read incorrectly.
- Characters a charset cannot hold are never sent as `&#NNN;` or `?`: the message is not sent and the characters are named.

## FHIR and FHIRPath

- FHIR XML is read with the same types as JSON (booleans, numbers, lists), so XML and JSON resources validate and evaluate alike.
- `ofType()`, `is` and `as` on choice elements use the type in the element name.
- `resolve()` matches type, server and version exactly, and resolves contained resources in Bundle entries.
- Integer arithmetic is exact, and date arithmetic handles 29 February.
- Extensions on primitive values are visible to FHIRPath and validated.
- Deeply nested expressions and documents are refused with an error instead of stopping the app.
- An installed R5 package no longer changes how R4 resources are checked.
- Package installation has size limits for safety.
- The FHIRPath panel and the Bundle visualizer are translated; out-of-date results after an edit are marked.
- The FHIR rules builder keeps settings it does not manage, detects changes made on disk, and never empties a file it cannot read.

## Communication (MLLP, HTTP, SOAP)

- The MLLP listener serves every message on a connection, and Stop closes open connections.
- Messages over 10 MiB are refused with AR.
- The new *Auto* encoding follows MSH-18 when sending and receiving.
- HL7 segments go on the wire with CR, also in HTTP and SOAP bodies.
- ACKs mirror the message they answer (separators, sender and receiver, version, processing ID, charset), each with its own control ID.
- History logs received messages and shows the target, size and full request and response for the latest 100 entries.
- Passwords and API keys stored in the history by older versions are removed at the first start.
- HTTP redirects to another server are shown instead of followed; credentials in URLs are redacted in the history.
- SOAP custom templates keep WS-Security and WS-Addressing headers; CR is preserved in XML payloads.

## Anonymization and tools

- The PHI catalogue covers 89 fields (see above).
- Dates are masked to a valid 1900-01-01 of the same precision, so anonymized messages validate clean.
- Batch anonymize and the generator's "Save all to folder" never overwrite existing files, links included.
- Anonymize, Export and Copy Truncated act on the text in the editor and on the tab where they were started.
- CSV exports start with a UTF-8 byte order mark, so Excel shows accented names correctly.
- Negative numbers stay numbers; JSON exports keep field order.
- Templates use local time with offset and a unique MSH-10; the SIU and MDM templates validate cleanly; templates and samples are translated.
- The Test Case Library search includes message text and expectations.

## Plugins

- Enabling or disabling a pack applies everywhere, the CLI included, and only to that pack.
- Packs with a duplicate id are refused and listed with the reason.
- Validation rules check each repetition, count characters and report patterns that do not compile.
- PHI masking from packs is exact, including MSH fields and repetitions.
- Packs with a byte-order mark or an uppercase `.JSON` extension load, and loading problems are listed in Settings.

## Command-line tool

- A pattern that matches no file, a resource that could not be fully checked, or a charset that cannot be decoded is reported with a non-zero exit code.
- Patterns ignore case on every OS.
- Output files are written atomically and never replace a read-only file.
- `send` bounds its write time, handles files with several messages, and does not accept an ACK for another message.
- On a terminal, `anonymize` prints UTF-8; control characters in reports are escaped.

## Licensing and privacy

- Renaming the computer no longer affects the trial or the licence: the hardware ID now comes from the operating system's machine identifier. Existing licences keep working.
- Licences activated online are re-checked about once a week; a revoked code returns the app to Community.
- An expired or non-applicable licence can be removed with Deactivate.
- On Windows, the second copy of the trial record is kept in a separate folder.
- The machine ID is read through the registry API.
- Cleared session, history and profiles are removed from the database file.
- On Linux the database is readable by its owner only.
- Every package now includes the complete licence text (MIT and Business Source License 1.1).

## Platforms and documentation

- macOS 11 or later is required.
- The manual, the site and the README describe the product as it is, in all five languages.
