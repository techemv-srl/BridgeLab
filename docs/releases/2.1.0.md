# BridgeLab 2.1.0 — what's new

BridgeLab 2.1 reads HL7 v2 messages in plain words, ships the command-line tool as a container image, and brings the components it is built on up to date. The [CHANGELOG](../../CHANGELOG.md) has every detail.

## Reading a message in plain words

**View → Interpretation** (`Ctrl+Shift+E`) opens a panel that reads the open HL7 v2 message as sentences, one block per segment, in the language of the interface:

> **PID** Patient Bianchi, Laura Maria, Female, born 1974-03-22, identifiers MRN100245 (Medical record number).
> **PV1** Visit: Inpatient, in CARD, room 204, bed B, attending doctor Verdi, Marco (DOC4410).
> **OBX** Hemoglobin [Mass/volume] in Blood (718-7): 11.9 g/dL, reference range 12.0-16.0, Below low normal, status Final results.

- Names, dates, places and identifiers are written the readable way, and codes come with their meaning from the HL7 value tables.
- Every value is a link: a click selects that field in the editor and in the tree.
- MSH, EVN, PID, NK1, PV1, ORC, OBR, OBX, AL1, DG1 and NTE have their own wording. Any other segment, Z-segments included, is read field by field with the field names of the message's HL7 version.
- The panel follows the message as you edit it. A long result is drawn 200 segments at a time.

The meanings of the codes come from the HL7 tables and are in English in every language.

## The CLI as a container image

From this release `bridgelab-cli` is also published as `ghcr.io/techemv-srl/bridgelab-cli`, tagged with the version and `latest`, for CI pipelines that run containers:

```sh
docker run --rm -v "$PWD:/work" ghcr.io/techemv-srl/bridgelab-cli validate "messages/*.hl7"
```

The [CLI README](../../tools/bridgelab-cli/README.md) has a GitLab CI example and shows how to keep the files you write owned by your user. `bridgelab-cli --help` and each command's `--help` now end with a few ready-to-use examples.

## Smaller improvements

- **"Opened as text" says why.** When a file opens as text, the dialog now gives the reason in your language and suggests a fix, for example a missing `M` at the start of `MSH`, a header in lower case, something before the header, or JSON with a syntax error (with its line and column).
- **FHIRPath boundaries.** `lowBoundary()` and `highBoundary()` work on decimals, quantities, dates, dateTimes and times, computed exactly from the precision written in the value. The engine now passes 984 of the 1,053 runnable cases of the official HL7 FHIRPath test suite.
- **Build code.** About shows a build code next to the version (`Version 2.1.0 · Build 20261117.1a2b3c4`), and `bridgelab-cli --version` prints it too. If you contact support, please include it.
- **Unsaved tabs survive logging out.** When the system ends BridgeLab (log out, shut down, Quit from the Dock), unsaved tabs are kept even with session restore off, and offered at the next start.
- **Reload for FHIR packages**, and `--output FILE` for every CLI report (`validate`, `test`, `batch`), which Windows PowerShell 5.1 needs: there `>` writes UTF-16.

## Fixes

The most important fixes in this release:

- **Saving a restored tab no longer empties its file.** Ctrl+S pressed while a large restored tab was still being read wrote an empty file (also in 2.0.x). The save now waits for the read.
- **Anonymization masks indented and lower-case segments.** Segment lines indented with spaces or a tab, as in text pasted from an e-mail, or written in lower case, kept the patient's data in clear in the dialog, Batch anonymize and `bridgelab-cli anonymize`.
- **Several cursors cannot cut into a folded field.** A second cursor could type inside a fold chip, and the save then lost the folded value.
- **Large reports and huge values no longer freeze the window.** The Validation panel draws long reports a page at a time, and the full-value window shows the start of a multi-megabyte field.
- **The MLLP listener keeps working with the Communication panel closed**, and its counts cover every message, not only the last 200.
- **FHIR**: JSON array shape is validated, decimals read from a resource keep their precision in FHIRPath, and FHIRPath lists of hundreds of codes work.
- **Plugins**: packs with heavy patterns no longer stall startup and validation, and rules on a lower-case segment now work and are listed as warnings.
- **Linux**: exports save a name typed without an extension, and dropdowns are readable in the dark theme.
- **Robustness**: opening a very large file, a device or a pipe can no longer take the app out of memory (files up to 16 MB open at once, up to 64 MB after a question); a damaged database no longer stops the app from starting; a file name that is not valid UTF-8 no longer ends it; a reload asks first when it would lose unsaved work; closing the main window closes the manual too.
- **Saving** keeps a file's ACL and extended attributes, and the temporary file of a save is readable by its owner only.
- **Network**: requests to this computer never go through the proxy, and a refused certificate is reported as such instead of as a dead network.
- **CLI**: no escape sequence from a message, an ACK or a plugin pack reaches the terminal.

The full list is in the [CHANGELOG](../../CHANGELOG.md).

## Good to know when you update

- **Limits on runaway work.** One FHIRPath evaluation does at most 50 million steps in 60 seconds, and the FHIR rules of one validation share twice that. Past a limit the panel or the report says so, and rules left out are counted in one error. Validation runs off the window's thread, so open, save and the FHIRPath panel keep answering meanwhile.
- **MLLP listener.** It serves at most 64 connections at once, holds at most 64 MB of messages still arriving, and closes a connection whose message is not complete within 2 minutes of its first byte. A burst of received messages opens at most 20 tabs until you press a key or click; the others are in the console.
- **Large messages.** Pasting more than 16 MB of text asks first and more than 64 MB is refused, as for files. Sending a message over 10 MB by MLLP, HTTP or SOAP asks first, since many receivers refuse one that large (BridgeLab's own listener accepts up to 10 MB). Received messages stop opening in tabs by themselves after 16 MB in a burst, as after 20 tabs.
- **FHIR packages** install from a regular file of at most 256 MB that unpacks to at most 1 GB.
- **FHIR JSON array shape.** A resource 2.0 accepted can now report an error: an element that repeats is an array even with one item (`"name": [{…}]`), one that does not is never an array (`"gender": "male"`). `bridgelab-cli validate` checks the same, so a CI gate that passed on 2.0 can fail.
- **Right-click.** The webview's own menu no longer opens anywhere, text fields included: there Cut, Copy and Paste are Ctrl+X, Ctrl+C and Ctrl+V. The editor, the tabs and the tree keep their own menus.
- **Windows and panels.** F1 brings an open manual to the front, and the Communication panel opens tall enough to show all its settings.
- **Save As** offers the type of the tab (HL7, FHIR JSON or FHIR XML) and adds its extension to a name typed without one.
- **Links** in the editor (Ctrl+click), in About and in the manual open in your browser or mail client.
- **Request history** no longer keeps passwords and tokens found in URLs; the rows already saved are cleaned once, at the first start of 2.1.
- **Linux package name.** The .deb and .rpm are now called `bridgelab` (they were `bridge-lab`). Install the new package as usual: it replaces the old one in one step and keeps your settings, licence and saved tabs. Scripts that query or remove the package by name need the new name.
- **macOS shortcuts.** Show Segment in Tree is now ⌘⌥T and Copy Segment ⌘⌥C, so ⌥T and ⌥C type their characters again. ⌘H, full screen and Control-key text editing work again.
- **Shortcuts and dialogs.** With a dialog open, app shortcuts do nothing (F1 still opens the manual).
- **Delimiters.** A message header whose delimiters cannot be used (a tab, a non-ASCII character, one character twice, two encoding characters or fewer) now opens as text with the reason. Three encoding characters (`MSH|^~\|`) still open, with `&` taken for the subcomponent separator and a validation warning (MSH-006).
- **Character sets when sending.** In Auto encoding, MLLP (app and `bridgelab-cli send`) refuses a message whose MSH-18 names a character set BridgeLab cannot write, and messages of one tab or file that declare different character sets when sending them together would change their text. Choose the encoding in the advanced MLLP settings (`--encoding` in the CLI) to send them anyway.
- **Replies that are not an ACK of the message.** An MLLP reply that is not HL7, whose MSA-2 names another message, or whose MSA-2 is empty when the message sent has an MSH-10, is no longer shown as accepted (the CLI exits 1). A receiver must repeat the sent MSH-10 in MSA-2.
- **`to-json` and Export JSON** turn a file of several messages into a JSON array with one document per message.
- **Machine policy on Windows.** `policy.json` is honoured only when the file and its folder belong to Administrators or SYSTEM. An unusable `policy.json` is named in Settings → Privacy.

## Updated components

BridgeLab 2.1 moves its desktop framework to Tauri 2.12 and its interface to SvelteKit 3 and Vite 8. It also updates the libraries it ships with to their latest patched releases, among them SQLite 3.54.1, the updater's archive library, and the TLS certificate and networking libraries. We recommend updating.

If you build BridgeLab from source, you now need Node.js 22.17 or later.
